# 通用项目交付复核清单

本清单适用于从底座派生的项目。它定义开发与交付检查要求，不表示底座已经实现所有辅助组件，也不预设具体角色、业务状态或视觉风格。

## 一、视觉与素材样板

- 先确认首页、列表、详情及一个管理表单的代表样板，再推广全站。
- 确认实拍或示意素材方向、裁剪比例、缺省图、替代文本与来源记录。
- 业务上传图片优先；缺省图不得暗示未经验证的真实业务事实。

## 二、连续操作与请求边界

- 从记录 A 切换到 B、组织 A 切换到 B，以及查询参数变化时，核对标题、内容、列表与权限范围同步。
- 延迟 A 请求并切换 B，验证 A 晚返回不会覆盖 B。组件按路由重建只能解决部分刷新问题，仍需核查未完成请求。
- 连续触发提交，包含异步表单校验阶段，确认只发出一次修改请求；校验不通过和请求失败后可以再次操作。
- 列表分别检查加载、有数据、成功为空、失败与重试。失败时不显示“没有找到”。
- 首页搜索、列表筛选、刷新及浏览器返回的查询条件保持一致；筛选回首页，删除末页最后一项后回退到有效页。
- 根据实际业务身份验证默认入口、刷新恢复与安全返回地址；前端导航不能替代后端授权。

## 三、最终产物冒烟检查

在隔离数据库及独立会话中使用最终交付产物验证，不以 Vite 开发服务结果替代。

- 前端构建完成后重新整合打包，记录提交号、工作区状态、产物名称与 SHA-256。
- 游客访问门户和登录页面，检查全部本地素材 HTTP 状态、类型与实际显示。
- 直接打开并刷新深层路由；同时验证匿名访问受保护 API 仍被拒绝。
- 验证登录、刷新恢复、退出及至少一条真实核心业务链。
- 涉及上传时，验证类型/大小、展示，以及服务重启后文件仍可读取。
- 启动入口检查 Java、必要配置、产物路径、端口占用和可读错误；不输出实际凭据。
- 在干净环境按 README 启动。环境缺失时记为未验证，不能预填通过。

## 四、浏览器上下文与预览

- 桌面与窄屏使用独立测试上下文，不在用户页面设置视口、设备模拟或调整窗口。
- 检查整页横向溢出、局部宽表滚动、弹窗及抽屉提交区域是否可达。
- 用户预览使用原生视口（如 Playwright 的 browser.newContext({ viewport: null })）。
- 额外在原生大窗口检查铺满、居中与溢出，结果与固定尺寸测试分别记录。
- 若出现右侧或底部大片白区，先比较 innerWidth/innerHeight 与 outerWidth/outerHeight，排查模拟视口残留，再定位 CSS。
- 完成后只关闭本任务创建的测试上下文，保留用户页面。

## 五、部署范围与证据

- 分别记录应用运行位置、数据库位置、数据来源、上传目录、配置方式与启动入口。
- 明确是初始化演示数据还是全量迁移；已有数据库不直接执行初始化或清空脚本。
- 按需验证数据库和上传目录备份恢复；凭据通过安全渠道配置，不加入普通源码包。
- 使用 docs/templates/delivery-verification.md 建立唯一汇总，区分通过、失败、跳过、未验证及沿用历史证据。
- 性能记录绑定数据库位置、数据规模、并发、版本和环境；切换云库后不能把本机历史结果写成本轮实测。
- 截图或结果文件若被 Git 忽略，交付时单独保留并在汇总列出位置；不要把包含隐私或凭据的证据公开提交。

## 后续代码改进方向

优先评估统一提交控制、列表状态与查询同步、路由数据刷新及最终产物冒烟脚本。实现时结合底座现有代码复用，补充能复现异步校验重复提交、旧响应覆盖等行为的测试。不要把具体项目角色、表结构、素材或测试数量固化进框架。
