# 毕业设计全流程 SOP：从接收选题到最终交付

整理日期：2026-10-17。适用对象：基于现有框架开发的管理系统、预约平台及同类软件毕业设计。

本文由实际项目流程提炼为通用执行规范；示例流程不代表新项目已完成开发或通过验证。更细的工程操作见 [底座开发 SOP](starter-development-sop.md)。

## 1. 总流程与完成原则

接题建档 → 需求与范围 → 检查框架和环境 → 页面与视觉 → 开发计划 → 系统设计 → 业务开发 → 联调验收 → 简化启动与迁移 → 报告与配套材料 → 打包复核 → 接收者验收 → 归档维护。

- 每个阶段必须有产物和完成条件；代码写完、效果图生成、文件导出均不能单独作为交付完成依据。
- 开发、论文、答辩 PPT、项目简介、部署分别登记范围。后来新增的工作同步进入计划，不受早期“本期不含论文”等旧范围限制。
- 用户已明确的要求直接执行；仅对影响业务含义、已有数据处理或交付范围的缺口询问。
- 需求、代码、数据库、页面、报告和演示材料必须一致。发生变化后更新受影响材料。
- 所有状态使用“待开始、进行中、待验证、已完成、受阻”；检查结果使用“通过、失败、跳过、未验证”。

## 2. 接收选题与建立项目档案

**输入：**选题或候选方向、任务书、学校要求、交付期限和已有资料。

1. 登记学生姓名、学校、专业、题目、指导教师、各阶段截止日期；未提供的信息留待补，不编造。
2. 收集任务书、开题要求、论文模板、排版规范、参考论文、PPT 参考和项目简介样例。
3. 确定交付内容：源码、SQL、可运行程序、使用教程、报告、项目简介、PPT，以及是否需要视频和服务器部署。
4. 区分开发电脑和接收者电脑的环境，提前询问最终如何启动、是否联网、是否使用云数据库。
5. 已有项目先识别现有文件和用户修改；新项目建立独立目录，记录框架来源及提交版本。
6. 未定题时提供候选题和主要功能，定题后固定正式名称；候选资料按用户要求处理。

**产出：**`docs/project.md`、资料清单、交付范围及待补信息。

**完成条件：**知道为谁做、做什么、何时交、交哪些文件，以及接收者怎样运行。

## 3. 编写需求与控制变更

**输入：**确认的选题和范围。

1. 列用户角色、门户功能、管理功能、主要实体和至少一条完整业务流程。
2. 每项需求写明入口、输入、权限、业务规则、结果和失败反馈，并分配需求编号。
3. 对预约、订单、审批等建立状态表，明确操作者、前置条件、状态变化、撤销和重复操作规则。
4. 明确日期、时间、数量、金额、归属、历史保留及并发冲突等规则；建议值与已确认值分开。
5. 确定注册、上传、支付、短信、定位等是否需要；模拟能力在页面与文档标明。
6. 写出可执行验收条件，覆盖正常流程、非法参数、权限和实际相关的边界。
7. 新需求登记“原规则、变更内容、影响页面/接口/表/测试/材料、进度影响、决定来源”，同步更新需求和计划。

**产出：**`docs/requirements.md`、验收清单和变更记录。

**完成条件：**每项核心功能都能判断是否完成，关键业务规则没有未标注的假设。

## 4. 检查框架和运行环境

1. 阅读 AGENTS.md、README、实际依赖清单及相关文档。代码探索按项目 CodeGraph 规范执行；工具失败时正常降级。
2. 核实登录、权限、请求封装、分页等已有能力，区分实际实现和示例占位。
3. 列“复用、替换、新增、退出”四类内容；不继续无关框架建设，不为了新选题随意升级依赖。
4. 核对 Java、Node/npm、Maven Wrapper、MySQL、端口和数据库用途。优先复用现有环境。
5. 建立独立测试数据库，记录底座测试、构建和启动结果；缺环境的检查明确标注。
6. 数据库凭据使用环境变量或约定的本地配置，不写入普通文档、截图和公开仓库。

**产出：**环境与底座检查记录、问题清单、开发和测试配置说明。

**完成条件：**复用边界清楚，能够解释环境问题与业务开发问题。

## 5. 页面与视觉设计

1. 根据需求列页面、路由、角色、入口和主要操作，再设计页面。
2. 项目已有门户效果图时，制作前阅读其素材说明并查看对应原图；没有效果图时先建立视觉基准。
3. 需要逐页预览时按页面数量生成效果图；用户要求先不写代码时，仅完成设计和归档。
4. 统一品牌、配色、字体、导航、间距、卡片、表单、状态和窄屏行为；门户与管理端采用各自布局。
5. 图片归档时附页面映射、来源、生成记录和偏差校正说明。
6. 业务规则遵循需求；生图中的错误时间、状态、文案和按钮必须校正。运行截图在系统实现后另外获取。

**产出：**效果图、素材索引、`docs/pages.md`。

**完成条件：**每页知道参考什么、展示什么、能够执行什么操作。

## 6. 制定计划与系统设计

1. 将需求拆成可以独立验收的任务，登记负责人、依赖、文件范围、完成标准和证据位置。
2. 优先贯通一条“数据库 → 接口 → 页面 → 持久化”的核心流程，再扩展其他功能。
3. 固定项目名、包名、目录、API、分页、错误响应、字符串 BIGINT ID、时区和状态枚举。
4. 设计独立业务表、唯一约束、索引、历史快照、事务和按实际风险需要的并发控制。
5. 区分新库初始化、已有库升级和恢复；迁移前备份，禁止默认覆盖用户数据。
6. 只有用户或适用规范明确授权时才拆分多智能体；分工前固定公共契约，完成后统一集成验收。

**产出：**开发计划、进度表、架构/接口/数据库文档、SQL。

**完成条件：**实现顺序明确，前后端字段一致，数据保留和升级路径清楚。

## 7. 按完整业务链开发

每条业务链重复以下步骤：

1. 对照需求编号、状态规则和页面参考，确定本条链路的完成条件。
2. 实现数据库与后端规则：受控输入、角色、数据归属、合法状态、事务和必要的冲突处理。
3. 封装业务 API，再接入门户与管理端真实数据和操作。
4. 补齐加载、空数据、校验、提交中、成功、业务失败和网络失败反馈。
5. 检查写入后刷新仍存在，不用固定数字冒充数据库统计。
6. 执行关联测试并修复，更新进度与文档，形成可审阅版本。

沿用 Session、CSRF 和 BCrypt；后端验证权限与归属；401、403 分别反馈；写请求失败不自动重放。移除无关示例入口，已有数据按迁移规则处理。

**完成条件：**用户和管理员能实际完成对应操作，数据持久化，关键边界有证据。

## 8. 联调、测试与验收修复

1. 建立“需求编号 → 测试用例 → 实际结果 → 证据”的对应关系。
2. 验证登录退出、刷新恢复、角色隔离、本人数据范围、查询分页、CRUD 和完整业务链。
3. 根据选题验证非法参数、无效状态、重复提交、库存不足、时间边界或资源冲突。
4. 数据库行为在隔离测试库验证；不得为测试方便清空演示库或真实业务库。
5. 运行项目已有前端测试和构建、相关后端测试和打包，检查跳过项及其原因。
6. 浏览器检查门户与管理端、深层路由刷新、错误反馈和窄屏布局；不同账号使用独立会话或先退出。
7. 问题登记复现步骤、预期/实际结果、修复和复验结果；修改涉及的材料一起更新。
8. 记录日期、版本、环境和限制。历史测试数字不能直接当作当前版本重新测试结果。

**产出：**验证记录、截图、问题闭环清单、演示脚本。

**完成条件：**核心链路通过相应验证；尚未验证的项目清晰列出，没有把跳过写成通过。

## 9. 简化启动、数据库迁移与换机验证

1. 默认交付模式：接收者安装 Java 17 和 IDEA、配置可用 MySQL 连接、导入 Maven 依赖后，直接运行后端主类访问 `http://localhost:8080`。
2. 前端源码和最新 `backend/src/main/resources/static/` 同时保存并纳入版本管理。默认启动与构建不能依赖接收者安装 Node/npm 或先执行 Maven compile。
3. 开发者改前端后，在 backend 执行 `./mvnw.cmd -Pbuild-frontend clean package` 更新 static；核对 index.html 引用的 JS/CSS/图片存在。
4. 验证默认 Maven 构建不调用 Node/npm，JAR 包含页面，首页及深层路由可访问；不能仅验证 Vite 开发地址。
5. 如迁移云数据库，先确认迁移现有数据还是新建演示库；完成备份、导入、表和数据核对、应用账号连接及业务读写验证。
6. 区分“数据库在云端”和“网站服务已上线”，分别验收，不能互相替代。
7. 云连接可用时接收者无需本地 MySQL；仍需验证网络可达、配置读取和数据库权限。
8. 数据库配置加载方式以目标项目实际实现为准；如采用根目录 .cache/cloud-db.env，须实现并验证不同启动工作目录下的读取，再写入启动说明。
9. 最终从解压出的交付副本检查启动，避免依赖开发机缓存、旧进程或源码目录之外的文件。

**产出：**更新的 static、启动说明、数据库连接说明和换机验证记录。

**完成条件：**说明中的实际启动方式已经验证；无法实机换机时明确写出验证范围。

## 10. 毕业报告、项目简介与答辩材料

**输入：**稳定系统、真实设计与验证证据、学校模板及已确认的材料范围。

1. 报告先核对学校模板、封面信息、章节、字数、字体字号、行距、页码、目录、图表和参考文献要求。
2. 根据实际系统写需求、设计、实现和测试；设计图与代码/数据库一致，系统截图来自实际运行，未实现能力放入展望。
3. 图表按学校要求制作并保存图源；优先使用随仓库提供的 diagram-design。报告生成时按适用技能执行。
4. 参考文献检索并核验来源、作者、年份和出版信息，正文引用与条目对应；书目核验不能描述为全文阅读。用户要求先确认时，先列候选再写入。
5. 报告导出后渲染检查封面、目录、分页、图表、页码和参考文献，保留可编辑稿。
6. 用户手工调整过的最终稿单独保留；后续同步技能或规则时不得覆盖已完成报告。记录最终文件校验值有助于核对。
7. 项目简介按参考样例的结构与版式编写；可采用背景、技术与功能、项目意义三段式，导出 Word 后仍需渲染检查。
8. PPT 先定大纲和时长，再制作架构、流程、数据库、功能、测试及总结页；内容与报告、系统一致，未提供身份信息不编造。
9. PPT 逐页检查文字、图表、截图和播放效果，说明是否可编辑。如采用整页图片型 PPT，须告知文字无法单独编辑；需要可编辑文字时采用相应制作方式。
10. 使用教程涵盖全部角色、账号、入口、业务链、异常情况及启动停止方式；需要时提供中文命名 Word。

**产出：**报告、项目简介、PPT、使用教程及配套图源/截图。

**完成条件：**材料与真实功能一致，排版已经检查，待补信息和格式限制已注明。

## 11. 整理交付目录与制作压缩包

以下为可复用的四类目录示例，按当前用户要求调整姓名、系统名称和材料范围：

```text
姓名-系统名称-毕业设计交付/
├─ 毕业论文/                 最终报告，可按要求附 PDF
├─ 毕业论文简介/             项目简介 Word
├─ 系统名称/                 完整源码、SQL、文档、启动说明
└─ 系统名称PPT/              最终答辩 PPTX
```

源码目录必须包含：backend 源码、pom、Maven Wrapper 及 `.mvn/`、最新 static 全部资源、frontend 源码及锁文件、database SQL、必要 scripts、README 和维护文档。

打包检查：

- 保留原文件，以复制方式整理；核对最终版本，不单凭修改时间判断论文是否包含人工调整。
- 排除 node_modules、target、frontend/dist、.git、IDE 缓存、日志和无关临时文件。运行 JAR 如需交付，另设运行包。
- 普通或公开源码包排除实际数据库凭据，仅提供配置样例和配置方法。
- 只有当前项目用户明确授权时，才将数据库配置加入指定私人交付包；如采用 `.cache/cloud-db.env`，保留相对路径且仅加入该文件，不包含其他缓存。
- 私人包注明“含数据库配置、仅限私下交付”，不要公开上传；说明文件无法技术上保证不被转发。私人包授权不得跨项目复用。
- 核对 static/index.html 引用资源、压缩包目录、源码完整性及配置位置；从解压副本执行交付检查。
- 生成交付清单，记录文件名、版本、日期、SHA-256、检查结果和已知限制。

**完成条件：**包内文件完整、版本一致、无无关缓存，凭据处理符合具体交付范围。

## 12. 接收者验收与最终归档

1. 按用户指定方式交付具体文件，提供“先看这里”的环境、导入、启动、入口、账号、操作及停止说明。
2. 接收者解压并导入 backend/pom.xml，选择 Java 17、完成依赖下载、配置数据库、运行主类。
3. 按演示脚本完成用户与管理员核心流程，验证页面加载、数据写入及刷新。
4. 确认报告和 PPT 能打开，题目姓名一致，已知待补项得到处理；图片型 PPT 的编辑限制提前说明。
5. 反馈归入缺陷、环境问题或新增需求；缺陷修复后复验，新需求更新范围、计划和材料。
6. 修改代码后重新构建、更新 static、重新打包和更新校验值，不只发送无法识别版本的零散文件。
7. 记录接收者、交付日期、版本、验收结果、遗留事项和约定维护范围；未实际收到验收反馈时标为待验收。
8. 归档最终源码版本、交付包、报告、简介、PPT、图源及证据；敏感配置按私人范围保管。

**完成条件：**交付文件已核对，接收者完成约定验收，遗留事项和后续责任明确。

## 14. 通用项目使用说明

- 本文是执行目标，不宣称框架已经实现云数据库配置读取、前端 static 更新或简化启动；实施时核对实际代码与构建配置。
- 需求、设计、开发、验证、报告和交付均按当前项目事实填写，不继承来源项目的测试结论、业务规则、姓名或凭据授权。
- 两个项目级技能位于 `.agents/skills/graduation-report/` 与 `.agents/skills/diagram-design/`，拉取时保留隐藏目录，无需安装至个人技能目录。调用及环境说明见 [技能使用说明](project-skills.md)。
- 报告模板优先采用用户当前提供的版本；附带学校配置仅在用户选择该模板时使用。
- 每次实际交付重新核对文档排版、身份信息、PPT 可编辑性、源码包内容和解压副本启动。
