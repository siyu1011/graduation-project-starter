# 第一版页面与交互

## 页面范围

| 路由 | 谁可访问 | 内容与操作 |
|---|---|---|
| / | 所有人 | 门户首页，项目名称、简短说明；未登录显示登录按钮，已登录显示“我的记录” |
| /login | 所有人 | 用户名、密码、登录按钮、失败提示；已登录可跳转首页 |
| /portal/records | USER、ADMIN | 自己的记录列表，关键词/状态筛选、分页、详情、新增、编辑、删除 |
| /admin | ADMIN | 简单管理首页、身份和业务管理入口，不加入图表 |
| /admin/records | ADMIN | 全部记录列表，同样支持CRUD；显示记录归属账号 |
| /403 | 所有人 | 无权限说明和返回首页 |
| 未匹配路由 | 所有人 | 404与返回首页 |

门户使用顶部导航，管理页使用侧边菜单；同一账号会话。管理员登录默认进入 /admin，用户进入 /portal/records；URL 直接访问受保护页面先加载当前用户再做路由判断。只有同源相对路由可作登录后返回地址；普通用户不得被返回到管理路由。

首页是框架导航示例，不要求公开展示他人的业务数据。未提供独立个人中心或账号管理页面。

## CRUD 示例

示例“记录”字段：标题、描述、状态（ENABLED/DISABLED）。列表显示标题、状态、创建时间、操作；管理端另显示归属账号。详情展示全部非敏感字段。

搜索关键词匹配标题，状态可选，搜索后回到第1页；清空恢复默认筛选。默认每页10条，支持10/20/50；保存后刷新列表，删除最后一条时回退到有效页。

新增和编辑共用简单弹窗，标题必填且最多100字，描述最多2000字，状态默认ENABLED。提交时禁用按钮，成功提示并刷新，失败保留表单。取消删除不发送请求；确认删除后刷新。

普通用户新建记录归属自己；管理员在管理端新建也归属当前管理员，第一版不提供任意指定归属功能。门户不允许越权操作，管理端可以处理全部记录。

## 公共交互

加载、空列表、网络错误、校验错误均有明确显示。401 清空当前用户并引导登录；403 显示具体提示，不自动重试修改请求。退出清除前端会话状态并回门户首页。列表状态留在页面内，只将当前用户放 Pinia。

默认使用清晰的浅色布局、适当留白和一致按钮；桌面1280宽度正常，窄屏表格允许横向滚动。项目名称集中配置。公共组件最多先提取表格外壳和编辑弹窗，避免万能表单引擎。
