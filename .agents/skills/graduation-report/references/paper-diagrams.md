# 软件毕业论文图表规划

## 先区分表达目的

|设计视角|合适图种|不能直接替代它的图|
|---|---|---|
|某类用户如何完成操作|按角色的操作流程图|页面截图、状态图|
|系统如何校验请求并处理成功与异常|核心业务处理流程图|只有正常步骤的用户操作图|
|提供哪些功能、模块如何分层|系统功能结构图|前端—后端—数据库技术架构图|
|组件、层次或部署之间如何连接|总体架构图|功能模块树|
|身份校验、会话建立和角色分流|登录认证流程图|只有登录框的截图|
|实体之间的关联和基数|E-R图|单实体属性图、表格字段清单|
|一个实体具有什么属性|实体属性图|省略详细属性的E-R概览|
|业务对象如何迁移及哪些是终态|状态图|缺少状态边界的操作流程图|

功能、流程、实体及状态图应和正文、实际代码与SQL对应，不能为了凑图画出不存在的功能、表或可执行动作。

## 对照教师认可的参考论文

- 获取实际图或所在章节后确认语义；仅凭“系统结构图”“登录结构图”等模糊标题，不能判断其具体类型。
- 将参考图映射到本项目角色和业务，不照搬“学生”等不适用称呼。
- 重复题注可能是原文错误，不复制重复图名；不凭题注推断两个独立实体。
- 将适用但缺少的图纳入计划，在对应章节补足正文引出与解释。用户已确认的图表清单属于本次交付范围，应全部完成，或明确报告具体阻碍。

## 绘制与交付核对

- 过程用矩形，判断用菱形，起止用圆角端点；每个判断分支标注条件或是/否。重试、取消、拒绝和终态应与实际权限及时间条件一致。
- 功能结构图与技术架构分别命名，不能都笼统称为“系统结构图”。
- 实体属性图采用明确的矩形实体、椭圆属性等语义表示。图种工具没有相应规范时，可用确定性SVG等工具绘制；不能拿列表卡片或物理表结构截图冒充。
- 属性较多时拆分为同一图号下的子图，注明重复矩形是同一实体。主键、归属、状态和核心业务属性不能因缩图而丢失；只展示主要属性时，明确说明并保留完整数据字典。
- 时间区间、取消信息等复合属性需在正文说明其对应字段；计算列标注由系统生成，不作为用户输入。密码只能表述为哈希，不在图中出现实际密码、令牌或真实个人资料。
- 图中文字、形状与连线在论文实际插入尺寸下检查；复杂图可分子图跨页排放，每个子图有自身标签，末幅与总图题保持同页，不将整张复杂图缩至难以阅读。
- 新增图后按实际出现顺序连续编号，同步Markdown、Word正文引用、题注、清单与证据记录。旧证据记录作为历史保留，当前图号另列最新版。
- 修改Word时避开目录域中的同名缓存条目，以正文标题、样式或书签定位；更新目录不得删除新增内容。编辑文字时保留原有图片、SVG及其关系，不能将含图像的空文本run重写为纯文本。
- 最后核对完整图数、编号唯一性、每图正文引用、原有截图和封面保留，以及目录更新后的实际渲染结果。
